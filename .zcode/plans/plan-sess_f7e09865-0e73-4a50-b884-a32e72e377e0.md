# lit-screener 通用化 + anammox 主题包 + 结构化输出/few-shot 增强（最终版）

## 设计原则
通用引擎 + 主题包目录约定：一个研究主题 = 一个自包含目录，换/加领域零代码改动。RRA 判定主干（双评审→一致采纳/分歧仲裁/兜底/组合校验/留痕）保持确定性不变；agent 能力只以"引擎增强"形式引入（②③），不做自主工具循环。

## Part 1 引擎通用化（一次性，所有主题受益）

### 1.1 Record 元数据扩展（records.py）
- `Record` 新增 `language` / `doctype` / `date`（默认 ""）
- 适配器解析：RIS（LA/TY/DA，DA 归一化 ISO、失败回退 PY）；WoS/CSV 列（Language / Document Type / Publication Date）；OpenAlex（language/type/publication_date，date_from/date_to 下推 API filter）；S2（language/publicationTypes/publicationDate）

### 1.2 通用元数据过滤器（pipeline.py + cli.py + config）
```yaml
filters:            # 可整体省略=不过滤
  language: en      # 归一化（English→en）；未知语种保留交 LLM 判据兜底
  date_from: "2000-01-01"
  date_to: "2026-09-30"
  doctype_include: []
  doctype_exclude: [review, editorial, letter, meeting abstract, book chapter, news, correction]
```
`apply_filters(records, filters) -> (kept, drop_stats)`，表驱动实现；date 缺失有 year 时宽松判定；doctype 小写归一 + 子串匹配；统计进控制台与 stats_*.md。

### 1.3 system prompt 领域参数化（prompts.py + criteria.py）
CriteriaPack 新增 `domain` 字段；`SYSTEM_REVIEWER` 改为 `system_reviewer(domain)`；rare_earth.yaml 补 domain（向后兼容）。

### 1.4 知识库可选（pipeline.py）
`knowledge` 置空或目录无条目 → 跳过 RAG 不报错。

### 1.5 脚手架与预览（cli.py）
- `new-theme themes/<name>`：复制 `themes/_template/`（占位判据含"纳入/排除/边界"写法注释、knowledge.md、config.yaml、README 调优工作流）；判据就绪时顺带生成 labels 模板
- `--filter-only`：收集→去重→过滤输出保留/剔除清单，不调 LLM

## Part 2 anammox 主题包（首要任务交付）

```
themes/anammox/
  criteria.yaml      # domain: "污水生物处理与脱氮（环境工程）"；5 判据 + inclusion_logic: all
  knowledge.md       # ~12 条领域知识条目
  config.yaml        # 即拷即用：OpenAlex 查询、filters、recall、现有方舟模型
  labels_template.csv
```
- **A1 厌氧氨氧化核心**：anammox/deammonification/PN/A/CANON/OLAND/DEMON/SNAD/PdN-A 及 anammox 菌（Ca. Brocadia 等）须为研究对象；排除传统硝化反硝化无 anammox 环节、仅背景提及
- **A2 脱氮目标**：氮去除为核心目标/指标（TN/NH4-N 去除率、NLR/NRR/NRE）；排除氮仅附带参数
- **A3 废水处理场景**：城市污水主流/侧流、消化液/脱水滤液、渗滤液、工业废水、合成废水/模拟基质；排除饮用水、天然水体生态、土壤
- **A4 研究类型**：原创研究（实验或建模均可）；排除综述/评论/社论/书章/会议摘要
- **A5 语种**：English（metadata 硬过滤的 LLM 兜底）
- 知识条目：反应式与菌属、工艺家族术语、vs 传统硝化反硝化、一段/两段式与载体、主流 vs 侧流、基质类型、关键指标、FA/FNA 抑制、易混淆情形、海洋/土壤区分、规模术语
- 配置：mode=recall；query "anaerobic ammonium oxidation"（注释 title_and_abstract.search 提精度）；filters 2000-01-01~2026-09-30、en、排除综述等（原文"2026.09.31"按 09-30 处理）
- 现有 rare_earth 文件原地不动；根 README 补"新增主题三步走"

## Part 3 引擎增强（本次选定的 agent 能力升级）

### 3.1 ② 结构化输出（llm.py + prompts.py + pipeline.py）
- `LLMClient.complete_json(system, user, schema)`：优先走 `response_format` JSON 模式（OpenAI 兼容端点通用），返回 dict；失败自动回退现有"文本 prompt + 正则解析"路径
- prompts.py 增加评审/仲裁的 JSON 输出规范（schema：answers{判据:Yes/No}、reasonings、overall；仲裁另含 disagreement_root）；文本模板保留为兜底
- agent 配置增加 `structured: auto|text`（默认 auto：先 JSON 后文本）；trace 记录实际使用模式
- 效果：消灭 parse_error 路径的大部分来源；解析失败重试与人工兜底逻辑保留不动

### 3.2 ③ 金标准 few-shot 反馈（新 litreview/fewshot.py + prompts.py + config）
- 读取与 evaluate 同格式的 labels CSV，与 trace/题录文本连接，构建"人工裁定示例库"
- config：`fewshot: {labels: labels/anammox_golden.csv, k: 2}`（可省略=不启用）
- 评审 prompt 注入 top-K 参考例（标题+截断摘要+人工金标答案），按各判据正/负例均衡选取，哈希种子确定性采样保证可复现
- 人工标注累积后自动生效（重跑即用新示例），与 evaluate 形成闭环；仲裁 prompt 不注入（其已见双方推理链）

## Part 4 验证（依次）
1. `new-theme` 脚手架自测；含边界样例（中文文献/1999年/review/合成基质）的测试 RIS 走 `--mock` + `--filter-only` 验证过滤统计
2. 结构化输出：mock（文本路径）+ 真实 API 5 篇（JSON 路径与回退路径）均验证
3. few-shot：注入后 prompt 预览 + 真实 5 篇 smoke，确认格式与判定稳定
4. OpenAlex `--filter-only` 预览检索式命中 → `--limit 5` → `--limit 50` 试跑 → 人工核对 results.csv → 调 guidance
5. labels 模板 + `evaluate` 走通；论文 PDF 全文核验（退出计划模式后本地可读）
